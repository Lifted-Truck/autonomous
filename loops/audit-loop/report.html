A field guide · self-improving knowledge for coding agents

Knowledge that climbs: a hierarchical loop for making coding agents learn across projects

Most agent "memory" is per-project and stays there — every repo re-derives the same hard-won lessons. This is a portable system for letting knowledge climb: each project distills its own lessons, and a loop above harvests the ones that generalise and republishes them to siblings — recursively, all the way up a tree of projects.

The problem it solves

A single agent working in one repository can keep a durable record of what it learned there. But the moment you have many projects, three things go wrong: the same lesson is learned independently in five places; a genuinely universal insight stays trapped in the one repo that discovered it; and nobody has the incentive — or the vantage point — to notice the pattern across them. Human organisations have fought this exact battle for decades. This system borrows their answers and the answers from a fast-moving body of AI-agent-memory research.

The pattern: a recursive knowledge loop

Two loops, one shape. At the leaf, each project runs its own record-and-reflect loop across three small files. Above it, an audit loop harvests upward. Both use the identical entry format — so a grandparent scope harvests a parent with the very same procedure a parent uses on a leaf. The mechanism is self-similar at every level.

How a lesson earns promotion

Promotion is an untrusted write into a shared, high-trust store: a wrong lesson placed at a parent scope is retrieved and reinforced by every sibling below it, and the blast radius grows the higher it climbs. So trust is earned at the boundary, never inherited from whoever proposed it.

Qualified at source

Already trusted in its own project, or independently discovered by two or more siblings. Convergence from a shared source counts once, not twice.

Generalises beyond origin

You can state it without naming the origin project's code. The transferable pattern is promoted; the project-specific fact stays home.

Tightens with altitude

A group promotes on generality or convergence; the top promotes only what's proven across multiple groups. The higher it reaches, the more it must earn.

Provenance, never dropped

Every promoted entry keeps back-links to the exact source lessons and its own falsifier — so it can be traced, re-checked, and revoked.

Default-deny & quarantine

Single-source promotions enter provisional. When in doubt, the lesson stays in the child. Prefer not promoting over promoting unverified.

Dedup over abstraction

Merge convergent siblings into one entry and keep each origin's concrete detail. Aggressive summarising measurably destroys what makes a lesson usable.

Three sibling projects independently hit the same trap: an evaluation that compares against an idealised closed form, or runs in a benign regime, silently passes the very thing it exists to forbid.

One asserted a discretised value instead of the continuum ideal it was tempted to hard-code; one verified an operator by construction and gated a dense result as a set rather than index-aligned; one moved a test fixture into the frequency band where the forbidden shortcut and the correct method finally diverge. Different domains, one lesson — which is precisely why it promotes: before trusting an evaluation, prove it fails when fed the thing it is supposed to reject.

Where both literatures agree

Capturing and circulating a lesson is the easy part; the value is entirely in acting on it and not corrupting the shared pool. An observation does not become a lesson learned until behaviour verifiably changes.

The limit worth stating plainly

Observed ≠ Learned

Every human source — the Army, NATO, GAO, RAND, Google SRE — converges on one failure mode above all others: capture and dissemination masquerading as learning.

A promote-up loop that stops at publishing lessons into a store the agents read has done the disseminating 80%, not the acting 20%. Genuine learning means a promoted lesson changes downstream behaviour and the change is verified — bound into a rule the agent consults, a hook it runs, or a test that would have caught the original miss, then confirmed the failure does not recur. Any adoption of this system should treat that binding step as the real finish line, not the promotion.

Adopting it — and normalising across machines

The system is deliberately file-based and tool-agnostic: plain Markdown and JSON in each project, driven by portable setup and harvest prompts. Nothing is tied to one machine.

1
Seed each project with the leaf loop.Add the three files (protocol, index, library) to a project and reflect one real lesson per session. This is the substrate everything above harvests.
2
Light up a parent scope with the audit loop.Run the setup prompt at a directory whose children each run a loop. It installs the audit protocol, the index/library, and the state ledger, seeded only with lessons that already qualify.
3
Harvest on a cadence — in propose-only mode.Schedule the harvest to write a dated proposal rather than mutate the shared store unattended. Review, then apply. This is the staging-buffer defence the poisoning research demands.
4
Repeat one level up.Because every scope uses the same entry format, the next level harvests the last with the identical procedure. Grow the tree as your project structure grows.
5
Carry the kit between machines.Version the setup prompt, the harvest prompt, and the runner in one repo. On a new machine, clone it, point the runner's scope list at your local project root, and re-run. The per-project files travel with each project.

Where this is going

This is version one of a living practice, not a finished framework — every source above warns that a clean framework is an aspiration to be measured, not a truth. The intended arc is iterative: run real harvests, watch which promotions prove out, and fold each round of research back into the protocol. Two directions are already marked. Close the loop — move from disseminating lessons to binding and verifying them downstream, turning "observed" into "learned." And add a cross-cutting axis — a guild-style path so a lesson shared by siblings can travel between them, not only up to a parent. The structure is meant to absorb its own findings over time; that is the whole point.
